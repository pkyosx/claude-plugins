# spec 格式

看 `${CLAUDE_PLUGIN_ROOT}/skills/gap-swimlane/scripts/example-spec.json` 最快。座標由 `gen.py` 依泳道與欄位自動算，只有排不好時才手動指定。

## 文字欄位的格式

所有說明文字（`summary`、`note`、`detail`、卡片內容、`limits`）都支援這幾種標記，其餘照原文顯示：

- `**粗體**`、`` `code` ``、`[文字](https://…)`。
- `[[確認]]` 顯示成綠色標籤；`[[推論]]`、`[[部分推論]]` 顯示成紅色虛線標籤；其他 `[[文字]]`（例如 `[[已解決]]`）一律綠色標籤。

## 頁首

- `title`：頁面標題，也是 Artifact 名稱，例「SHOP-128 缺口泳道圖」。
- `summary`：一段話講這張票要做什麼、改動前缺什麼，以及「下圖是 PR 合併後的流程」。
- `pr_status`：PR 狀態，顯示在版本表的表頭括號裡，例「正式 PR、未合併」「draft，SHA 可能更新」。預設「未合併」。
- `note`：未驗證聲明與版本說明。沒有實際執行時，開頭寫「**只讀程式與留言，未實際執行。**」；實作者驗證過的版本、之後的 commit 是否改程式、來源不一致的處理，都寫在這裡。
- `prs`：每支 PR 一筆。
  - `key`：卡片引用時用的短代號，例 `orders`、`rules`、`admin`。
  - `name`：顯示名稱，例 `orders-api#412`；`short` 可另給卡片用的短名。
  - `url`、`base`（改動前的 merge base SHA）、`head`（PR head SHA；已合併的 PR 寫 merge commit），SHA 寫前 11 碼。
  - `ticket`：選填，這支 PR 屬於哪張票；`state`：選填，例「已合併」「未合併」「draft」。任一支 PR 有寫時，版本表多出對應欄位。

## 多張票

一頁涵蓋多張一起交付的票時（例如同一個功能拆成觸發、動作、畫面三張票）：

- `tickets`：每張票一筆 `{key, title, url}`，列在頁首摘要下方。只有一張票時可以省略。
- `acs` 每筆加 `ticket`（票號）；`tickets` 超過一張時必填。其他地方引用 AC 時寫成「票號 AC 編號」，例如 `"SHOP-130 AC-01"`，畫面上的 AC 標籤也這樣顯示。不同票可以有同樣的 AC 編號。
- 缺口卡片用 `tickets` 列出它服務哪幾張票。
- 每支 PR 用 `ticket` 標出所屬的票。

## AC

- `acs`：Jira 票 Acceptance Criteria 的清單，每筆 `{id, text}`。`id` 照票面編號（`AC-01`）；`text` 照原文，太長時只刪掉範例與細項，不改寫意思。
- 缺口卡片用 `acs` 列出對應的 AC id；節點自動繼承它所有缺口的 AC。節點另寫 `acs` 時改用節點自己的清單（例如同一個缺口跨多個節點，只有部分節點跟某條 AC 有關）。
- 點節點時跳出的視窗列出「相關 AC」的 id 與原文；缺口卡片顯示 AC id 標籤。
- 只有關聯明確才對應；對應不上的 AC 不要硬掛，也不要為了湊滿而改寫 AC。

## 泳道與節點

- `lanes`：由上到下。
  - `id`、`name`；`sub` 是名稱下方的小字陣列（例：服務名稱）。
  - `rows`：泳道裡有幾列，預設 1。分流結果要上下排開時加列。
  - `row_height`：每列高度，預設 84；列數多的泳道用 66。
- `nodes`：每個步驟一筆。
  - `id`、`lane`、`col`（從 0 開始的欄位，代表先後順序）、`row`（泳道內第幾列，預設 0）。
  - `title`：粗體標題，約 10 個中文字以內；`sub`：一行小字條件，約 13 個中文字以內。太長時 `gen.py` 會提示。
  - `kind`：`normal`（預設，一般灰框）、`fail`（停止、失敗或不發事件，紅框）、`risknode`（只為標示剩餘風險而畫的情境節點，紅色虛線框）。成功的終點用 `normal`。缺口與風險只靠節點上的 `gaps`、`risks` 徽章表示，框線不另外標示。
  - `gaps`：缺口編號陣列，只掛在 PR 實際新增或修改的步驟。既有、沒被修改的步驟即使是缺口發生的位置也不掛，必要時在 `sub` 寫「既有流程，本票沒改」。沒有缺口編號的節點，在圖例中代表「改動前就有、本票沒改」。
  - `risks`：剩餘風險或範圍外問題的字母陣列。
  - `detail`：點節點時跳出的視窗裡的說明，寫行為與依據（確認或推論），不放檔案路徑。
  - `eng`：選填，節點的工程依據（檔案、函式），放在視窗裡可展開的「工程依據」區。
  - `inf`：`true`（推論）或 `"part"`（部分推論），標在說明標題旁。
  - `acs`：覆寫繼承自缺口的 AC 清單。
  - `x`／`y`：手動指定中心座標，蓋過 `col`／`row`；只在自動排版放不下時用。

## 箭頭

- `edges`：每一條線。
  - `from`、`to`；`label` 是線上的短標籤，寫這一步在什麼條件下發生。
  - `risk: true`：紅色點線，連到 `risknode`，沒有箭頭。
  - `route`：線怎麼走，預設 `auto`。
    - `auto`：同一列 → `straight`；同一欄 → `vertical`；同泳道不同列 → `bus`；跨泳道 → `hv`。
    - `straight`：水平直線。`vertical`：垂直直線。
    - `hv`：先水平到目標那一欄，再垂直接到目標的上緣或下緣。
    - `vh`：先垂直到目標那一列，再水平接到目標的左緣或右緣。
    - `bus`：從右緣出來，在兩欄之間的空隙轉垂直，再水平接到目標左緣。一個分流扇出多個結果時，全部用 `bus`，線會共用同一條垂直段。`bus_x` 可指定垂直段的 x。
    - `vhv`：垂直、水平、再垂直。`mid` 指定中間水平段的 y，預設貼著目標泳道的上緣。
  - `points`：手動給整條線的轉折點 `[[x,y],…]`，蓋過 `route`。
  - `label_at`：手動指定標籤位置 `[x,y]`；`label_anchor` 是 `start`（預設，從這點往右寫）、`middle` 或 `end`（寫在這點左邊）。

座標參考：第 `c` 欄節點中心 x = 275 + 205 × c，框寬 172、高 56。

## 卡片

- `gaps`：PR 補上的缺口。
  - `n`（編號）、`title`。
  - `before`：改動前缺什麼；`before_basis`：依據，例「確認」「確認（程式路徑）」。
  - `before_inference`：改動前描述中屬於推論的部分；`before_note`：補充備註。
  - `after`：PR 補了什麼；`prs`：補這個缺口的 PR `key` 陣列；`acs`：對應的 AC id。
  - `eng`：工程依據（檔案、函式、commit），放在可展開的「工程依據」區。
- `risks`：仍未補上的風險，`key`（A、B…）、`title`、`text`（觸發條件與後果；兩項相近時寫明差別）、`basis`、`inf`、`eng`。
- `out_of_scope`：範圍外的既有問題，欄位同 `risks`，字母接在 `risks` 之後；`text` 要寫明合併 PR 不會引入這個問題。`risks` 與 `out_of_scope` 共用一組字母，不能重複。
- `risk_note`：選填，顯示在剩餘風險清單上方，例如複核期間被新 commit 修掉的風險。
- `ledes`：選填，覆寫三個清單的說明文字（`gaps`、`risks`、`ext`）。
- `limits`：頁尾「讀圖時的限制」，每條一段：圖沒涵蓋的範圍、依賴實作者說明的部分、找不到 refinement 頁時搜過哪裡、整理日期與事實來源。

## gen.py 會擋下的錯誤

缺必填欄位、`id` 重複（泳道與節點共用一組）、節點的泳道不存在、`row` 超出泳道列數、兩個節點位置相同、箭頭指到不存在的節點、節點的缺口或風險沒有卡片、卡片的 PR `key` 不在 `prs`、AC id 不在 `acs`。有錯誤時列出全部並結束，不產頁面。

版面問題只提示、不擋：線穿過不相干的節點、標籤壓到節點或彼此重疊、標題或小字太長。沒有問題時印出「OK」。
